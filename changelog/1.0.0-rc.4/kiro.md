# Kiro CLI adapter

- Add the built-in `kiro` adapter with managed/system/path CLI acquisition from Kiro's checksum manifest, isolated `HOME` / `KIRO_HOME`, selected skills, stdio ACP MCP configuration, steering, and native hooks. Unsupported remote MCP transports are surfaced as skipped diagnostics, and an explicitly selected workspace name cannot be replaced by a same-name runtime companion.
- Run structured sessions through Kiro's documented ACP wire with incremental tool events, native session id/load, permission interactions, cancellation, and single terminal-state handling. Whole-turn prompts have no fixed 30-second adapter timeout, the response bridge is available before the initial prompt can request input, and late terminal-state RPCs cannot reopen interaction UI. Native permission IDs carry structured scope semantics so Sender, Agent Room, and channels localize complete EN/ZH copy, visual tone, grouping, icons, and accessible action labels without adapter-owned mixed-language strings. Typed channel replies accept the displayed localized label, original native label/value, or number, while ambiguous aliases are rejected.
- Keep Kiro model selection native and fail closed: the static selector exposes only **Default**, while exact model IDs require live session advertisement. Non-interactive modes and remembered One Works session/project permission rules use only request-scoped native `allow_once` / `reject_once` and fail closed when unavailable. A persistent native option is selected only from an explicit current user response carrying that exact ID.
- Preflight managed tar/DMG paths and links before installation, stage releases atomically, and validate managed root/version ancestors under lock before executing a reused binary. Each Kiro process now receives an atomic private `0700` HOME; fixed session-home reuse, recursive replacement, and filesystem Keychain links are intentionally disabled because Node has no portable directory-handle-relative mutation primitive. Skill overlay names use portable safe leaves with isolated-root and symlink-ancestor containment checks.
- Keep Kiro/AWS credential-provider variables and shared config/credentials file locators process-only by removing raw, mixed/fully percent-encoded, nested URL/form, and base64 equivalents from both values and ordinary object/Map property names in caches, generated settings, and logs. Kiro runtime-protocol workspace-query-options artifacts are scrubbed before disk writes and regenerated from live process inputs instead of replaying redacted credentials.
- Use an original One Works neutral terminal-integration icon across the brand catalog, adapter package, model selector, and config UI. It contains no Kiro/AWS artwork or official purple trade dress and does not imply endorsement; “Kiro” remains only the visible product-name identifier.
- Report only Kiro-verified active effort state; unavailable, sparse, empty-setter, load, and direct-mode paths no longer echo an unapplied requested effort.
- Keep Amazon Q as a probed `q` migration alias instead of a second adapter. Authentication files and `~/.aws/amazonq` are never copied, and undocumented Kiro disk history is not exposed as importable history.
