# @oneworks/plugin-chrome-driver 0.1.0-beta.9

- Moved the External Browser capability page under the new host-owned External Control group in Settings.
- Split the capability page into host-native Connection, Advanced access, Website permissions, Web Frame, and Review & audit tabs so each task stays focused.
- Made advanced-access preferences configurable while disconnected, persisted the boolean choices in OneWorks, and synchronized safe defaults or saved values when a compatible browser connects. Settings is the sole preference writer; the extension popup now reports only the effective policy.
- Added an always-visible Chrome Web Store install entry beside browser pairing.
- Added persistent, connection-independent URL matching rules for “Always ask” and “Always allow”. Only URLs consumed by the typed operation participate; the bridge resolves the current tab URL before review, rechecks it immediately before dispatch, and fails closed on navigation or rule changes. Advanced access still requires exact per-use confirmation, and neither advanced-access nor Chrome permission gates can be bypassed by a site rule.
- Added capability-negotiated execution-time URL guards for Raw, sensitive typing, page capture, MHTML/PDF export, and bounded debugger operations. The wire contract carries a SHA-256 fingerprint of the complete canonical URL, including query and fragment identity, without disclosing those values. New bridges reject older extensions that cannot enforce the guard, and new extensions reject guarded commands from older bridges that omit it.
- Bound persistent debugger attachments to the exact target fingerprint, detached and cleared their event buffers on top-level document or same-document navigation, and made newly owned attachments clean themselves up when initialization or the immediate caller guard fails. Owner-aware detach reconciliation prevents a delayed Chrome detach event from clearing a successor attachment, and guarded debugger/raw results are discarded if navigation wins during verification or command execution.
- Revalidated visible screenshots, MHTML captures, and debugger results after Chrome completed the underlying operation so navigation or active-tab changes cannot return data from a different page.
- Made client hot reload explicitly renegotiate the existing content-script handshake, so browser pairing remains available after a plugin-only reload without requiring a full page refresh.
- Added redacted audit entries for advanced-access and website-permission policy changes, including changes made while the browser is disconnected.
