# Junie Adapter Guide

This package adapts the official JetBrains Junie CLI headless protocol to One Works.

- `src/auth-env.ts` is the exported source of truth for every Junie account/provider authentication environment key. Runtime child selection and task persistence filtering must consume its classifier and provider lists; representation-aware scrubbing removes known long credential echoes without globally replacing short/empty values.
- `src/runtime/shared.ts` owns session HOME/XDG containment, explicit config and asset staging, plan-mode fallback instructions, controlled CLI arguments, Linux credential-store locator validation, and applies the shared pure persistence scrub to staged `configContent`. The task base-cache sink applies the same policy to every effective Junie instance identity—including custom `packageId` aliases and package roots—across configs, asset configs, and every resolved/source config-state view before `base.json` is written, even when another adapter is selected; effective non-Junie overrides remain untouched. Junie runs also omit authoritative auth env keys and encoded echoes from the persisted clone while retaining live runtime/child values. Mixed URL scrubbing must continue after userinfo/query cleanup so path and fragment echoes are removed without dropping nonsecret routing content. Advanced args must reject every adapter-owned option name/equals/case form, confirmed or conservatively reserved alias, repetition, and the `--` terminator before prepare or spawn. Persistence scrubbing must not mutate the runtime config object or remove legitimate nonsecret content.
- `src/effort.ts` is the single source of truth for the pinned CLI effort set; model metadata, config schema, selectors, and runtime validation must consume it without clamping unsupported values.
- `src/runtime/session/` owns direct text and `json-stream` child-process lifecycles. Stream is the default because it can cache the native session id; treat an emitted id as tentative until a confirmed result and successful process completion, and never mutate cache on failure, cancellation, or resume-id mismatch. Direct create cannot promise resume.
- `src/protocol/json-stream.ts` projects only the official 2651.4.0 `CliStreamEvent` / `OutputWriter` wire fields. A successful terminal requires the pinned string `result` plus the serialized `errorCode` / `List<LlmUsageOutput>` shape before native-id commit. Unknown ordinary EAP-shaped types stay diagnostic; failure/terminal-shaped unknowns and incompatible wire shapes must fail visibly.
- `src/runtime/native-hooks.ts` and `src/hook-bridge.ts` own verified headless `SessionStart`, `PreToolUse`, `Stop`, `StopFailure`, and `SessionEnd` integration.
- `src/runtime/init.ts` and `src/paths.ts` own managed/system/path preparation and the conservative 26.8 / 2651.4 compatibility boundary. Junie selects the shared managed CLI `minimal` child-env policy for candidate probes, login-shell discovery, npm install/lifecycle descendants, and post-install probes; other adapters retain the shared legacy-inherit default unless they opt in.
- `__fixtures__/` contains a clearly labeled synthetic descriptor fixture and a deterministic fake CLI. It is not a real CLI capture.

Build Junie child environments from an empty object and explicit basic/project/hook/auth allowlists; refresh only the selected provider's authentication before each turn. On Linux, preserve only shape-validated `DBUS_SESSION_BUS_ADDRESS` / `XDG_RUNTIME_DIR` locators needed for the native credential store. Do not bridge or copy the real `~/.junie` directory, write credentials into session config, add history import without a stable verified schema, or claim interactive Plan Mode in headless operation. Read `.oo/rules/ADAPTERS.md` and `.oo/rules/adapter-design/` before changing runtime behavior.
