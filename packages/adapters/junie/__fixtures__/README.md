# Junie protocol fixture provenance

`junie-2651.4.0-a2ux-descriptors.jsonl` is a sanitized, synthetic sequence built from class and field descriptors found in the official `@jetbrains/junie@2651.4.0` release JAR (`junie-release-2651.4.jar`). It is not a captured CLI transcript and contains no user, account, project, prompt, or credential data.

The wire-level source is `CliStreamEvent` plus `OutputWriter`, which confirms the `session`, `step`, `system`, `error`, and `result` event types and the `type`, `timestamp`, `sessionId`, `message`, `name`, `details`, `output`, `result`, `changes`, and serialized `errorCode` fields. For the terminal event, `OutputWriter.close()` supplies a string `result` and serializes the `List<LlmUsageOutput>` property under the pinned wire name `errorCode`; each usage entry requires string `model` and integer `calls`, with optional numeric cost/token fields. The adapter validates that exact terminal shape before treating a turn as successful. The underlying A2UX descriptors explain how internal message blocks are rendered into `step` events, but raw A2UX objects are not claimed as the CLI wire schema. The fixture deliberately includes an unknown EAP-shaped event to verify forward-compatible diagnostics.

Separate isolated, no-auth probes of the same distribution reported `Junie version: 26.8.10 (2651.4)` and advertised exactly `low`, `medium`, and `high` for `--effort`. Embedded official help and argument descriptors were also used to confirm the `-a` / `-c` / `-p` aliases, `JUNIE_API_KEY`, and the selected-provider `JUNIE_*_API_KEY` / standard provider-key pairs. These facts drive constants and allowlists in the adapter; they are not represented as captured model output.
