# Browser Control Chrome Transport

This package is the current Google Chrome transport for the host-facing Browser Control capability. The product display name remains `Browser Control` / `浏览器控制` so future extension-capable browser transports such as Firefox can join the same capability without renaming the product. Chrome is the only supported external browser until another transport is implemented and validated.

- `extension/` owns Chrome API calls, optional-permission prompts, stable tab/frame/document identities, semantic page operations, bounded debugger domains, and the OneWorks Web handshake.
- `server/src/` owns the authenticated loopback request/ack bridge, pairing/reconnect state, high-risk confirmation grants, persistent website-permission rules, and redacted audit records. Keep URL matching in `site-permissions.ts`; apply the result in the existing confirmation boundary and recheck the live target URL before dispatch. The bridge is started by the normal workspace plugin runtime; users must not configure or manage it.
- `bin/` owns MCP schemas, per-target scheduling, workflow execution, compact results, and progressive step lookup. It may call only named semantic operations.
- `bin/extension-release.cjs`, `materialize-extension.cjs`, `package-extension.cjs`, `validate-extension-package.cjs`, and `publish-chrome-web-store.cjs` own Chrome version mapping, flavor materialization, deterministic ZIPs, release validation, and the Web Store V2 state machine. The official developer/Web Store artifact is the audited privileged flavor; base is the optional minimal artifact, and release code must never package E2E.
- `store-assets/` owns Chrome Web Store listing/reviewer copy, screenshots, and promotional images. These files are release inputs, not extension runtime assets, and must not enter the npm package or extension ZIP. Public extension privacy policies live in `.oo/docs/privacy.md` and `.oo/docs/en/privacy.md`.
- `assets/icon.svg` is the host-facing Browser Control icon. Keep it browser-neutral and extension-oriented; do not replace it with a Chrome logo or a generic fallback icon.
- `client/` owns the OneWorks connection/permission/recovery UI and Web bridge handshake. Reuse host UI primitives and tokens.

The plugin identity is `external-browser-driver` / `@oneworks/plugin-external-browser-driver`; repository config
must use only that identity and must not add a runtime alias for the former package name. The public Chrome extension
and Chrome Web Store product name is `OneWorks`. Keep the Settings capability page named `External Browser` /
`外部浏览器`, and preserve the Store ID, protocol, storage, global, and DOM identifiers. Chrome-specific tool,
bridge, storage, and extension-release identifiers describe the current transport and stay stable until an explicit
versioned migration exists.

Prefer named semantic operations. Arbitrary JavaScript/CDP, complete cookie values, and sensitive page fields may be exposed only through their dedicated advanced-access operations after an explicit OneWorks preference is enabled, synchronized into the connected extension's `chrome.storage.session` policy, exact target/origin binding, and server-enforced per-use R4 confirmation. Website permission rules match a restricted URL form without query or fragment, while execution identity is a separately negotiated SHA-256 fingerprint of the complete canonical URL; never put full query, fragment, cookie, or token values in the wire guard or its errors. Guard-required operations, including sensitive typing, must fail closed across extension/bridge version skew. Revalidate capture/debugger targets after asynchronous Chrome results and discard results when URL, window, active tab, document, or attachment ownership changes. Persistent debugger attachments are bound to that exact identity and must detach and clear event buffers on top-level navigation; delayed tab-only `onDetach` events must be reconciled against the current owner and actual extension attachment before clearing state. Plugin client activation must explicitly request a fresh content-script HELLO so HMR dispose/reactivate can rebuild the nonce-bound pairing state. Website permission rules may alter confirmation only for ordinary site-scoped operations whose typed handler actually consumes the matched URL; they must never bypass advanced-access confirmation or derive scope from ignored arguments. OneWorks Settings is the sole preference writer; the extension popup reports only the effective policy. OneWorks stores only the boolean preference; the extension remains the authoritative enforcement point for the active connection and capability set. Sensitive result pass-through must be allowlisted by the bridge from the actual operation name and must never enter audit summaries. Never expose the Chrome password vault, arbitrary filesystem paths, remote code execution, cross-origin bypasses, or silent permission grants. All page operations require `tab_id`; ref-bearing mutations require the snapshot/frame `document_id`. Keep one canonical tab target serial for the complete workflow and allow independent tabs to run concurrently.

Run `pnpm -C packages/plugins/external-browser-driver test`, `pnpm -C packages/plugins/external-browser-driver typecheck`, `pnpm -C packages/plugins/external-browser-driver package:extension:all`, and the repository typecheck after changes.
