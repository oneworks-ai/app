# Token 用量统计

One Works 会把支持的适配器和插件上报的 Token 用量汇总到统一页面。

## 从哪里查看

- 在 Launcher 中打开“用量统计”，查看所有已连接 workspace 和扩展数据源的汇总。
- 在 workspace window 的“配置 > 应用 > 用量统计”中查看当前 workspace。此入口默认不会混入其他 workspace。
- 在模型服务详情的“用量统计”标签中查看当前服务；账号详情中的用量默认收起，展开后会自动锁定当前账号和工具。

页面会按数据实际存在的维度提供模型服务、模型、账号、工具、设备、workspace、所属插件和同步插件筛选。只有一个可选值时不会展示多余的筛选项。也可以直接点击模型服务、账号或工具列表中的项目下钻，再回到总览。

## 数据来源

One Works 优先记录模型服务或 CLI 返回的真实 usage 字段。目前内置链路会接收 Claude Code、Codex 和 Kimi 等适配器能够提供的 Token 数据。比如 Claude Code 使用 Kimi API 时，只要运行时返回 usage，页面就能同时归类到 Claude Code 工具、Kimi 模型服务、具体模型和选中的账号。

并不是所有官方套餐账号或第三方代理都会返回 Token 或费用。没有 usage 的请求不会被猜成精确值；页面只展示已上报数据，并在数据源离线或覆盖不完整时给出提示。费用也仅展示服务端明确上报的金额。

## 多账号与 Relay

账号、模型服务和套餐账号都以稳定资源 ID 区分，因此同一模型服务可以关联多个账号。插件上报的数据会同时保留：

- 所属插件：谁创建并管理该模型服务或账号。
- 同步插件：谁把这条用量从另一台设备传输到当前 One Works。

Relay 等插件可以通过 usage source 扩展接口同步其他设备的观测记录和资源信息。相同观测 ID 会去重，累计统计与增量统计不会重复相加。这样全局页面可以合并多台机器，同时仍能按设备、workspace、账号和资源所属插件追溯。
